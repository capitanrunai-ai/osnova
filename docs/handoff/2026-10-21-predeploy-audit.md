# OSNOVA AI: локальний аудит перед публікацією

Перевіряється саме зібраний `dist`, включно з правилами `_redirects`. Робочий сайт не змінювався; push, деплой та реальні відправлення заявок не виконувалися.

**Підсумок: фінальна production-збірка успішна; невирішених помилок у локальних перевірках немає. Версія готова до вашого деплою.**

## Знайдено та виправлено

1. **Прямі адреси документів.** `/en/services/automation/index.html` та аналогічні адреси існуючих сторінок після гідратації ставали клієнтськими 404 і давали React #418. Роутер тепер розпізнає `index.html` як ту саму сторінку; canonical зберігає чистий URL.
2. **Гідратація 404.** Загальний англійський шаблон конфліктував зі збереженою мовою браузера. Для неіснуючих вкладених адрес також відрізнявся код розділу в шапці. Початковий рендер узгоджено зі службовим документом, помилки React усунено.
3. **HTTP-статус службових документів.** Для чотирьох локалізованих 404 та загального `/404.html` додано точні примусові правила зі статусом 404. Це запобігає HTTP 200 через пріоритет фізичного файлу; загальні правила для відсутніх URL збережено. Порядок обробки та file shadowing перевірено за [документацією Netlify](https://docs.netlify.com/resources/troubleshooting/request-chain/).
4. **Мобільні CTA SEO та AI Visibility.** Пізніше загальне CSS-правило перекривало адаптивну сітку. На 390 px текст і кнопка виходили за край екрана (наприклад, до 439–487 px). Відновлено одну колонку до 900 px, без змін десктопного дизайну.
5. **Перемикач прев’ю кейсів.** На смартфоні пререндер містив Desktop, а початковий React-стан уже був Mobile. Перше натискання Mobile не змінювало зображення. Початковий стан тепер відповідає HTML; мобільний режим встановлюється після гідратації.
6. **Production origin.** У локальному `netlify.toml` для production-контексту явно встановлено `SITE_URL=https://osnovaai.com`. Це знімає залежність canonical, sitemap та robots від локального fallback чи ручного налаштування змінної.

Удосконалено SEO-перевірку: `noindex` більше не може помилково пройти перевірку на `index`. Нові регресійні перевірки доступні через `audit:predeploy` та `audit:contact`.

## Що означають чотири 404

| Шлях | Призначення | Очікуваний статус |
|---|---|---|
| `/uk/404` | Український шаблон відсутньої сторінки | 404 |
| `/en/404` | Англійський шаблон | 404 |
| `/de/404` | Німецький шаблон | 404 |
| `/ru/404` | Російський шаблон | 404 |

Попередня кількість «4» означала чотири службові мовні документи, а не чотири зламані чинні сторінки. Додатково існує загальний файл `404.html` для адрес без відомого мовного префікса.

Шаблони мають `noindex, follow`, не мають canonical чи hreflang, не входять до sitemap; внутрішніх посилань на них немає. Неіснуючі адреси отримують відповідний локалізований шаблон зі статусом 404. Усі 84 чинні локалізовані сторінки мають залишатися HTTP 200.

## Відтворення перевірок

PowerShell, каталог проєкту:

```powershell
$env:SITE_URL = 'https://osnovaai.com'
npm.cmd run build:netlify
npm.cmd run verify:seo
npm.cmd run verify:analytics
npm.cmd run audit:predeploy
npm.cmd run audit:performance
npm.cmd run audit:contact
```

Ці команди створюють локальні файли й перевіряють їх; вони не публікують сайт. Збірку слід повністю завершити перед аудитами `dist`.

Фінальна production-збірка після всіх виправлень пройшла:

| Перевірка | Результат |
|---|---|
| SEO | 84 індексовані сторінки, 84 URL у sitemap; canonical, hreflang, метадані, robots узгоджені |
| Усі сторінки при 320 / 390 / 768 / 1440 px | 336 перевірок, без переповнення, відсутніх ресурсів чи текстів, змішування кирилиці з EN/DE або помилок JavaScript |
| Адреси зі слешем та `/index.html` | 168 варіантів чинних сторінок, HTTP 200 та правильний canonical |
| 404 | 20 локалізованих перевірок і загальний fallback зі збереженими мовами; очікуваний HTTP 404 та noindex |
| Посилання й ресурси | 1520 внутрішніх посилань, 40 унікальних ресурсів; відсутніх немає |
| Мови та меню | 84 перемикання мов зі збереженням маршруту, 12 перевірок мобільного/планшетного меню |
| Desktop / Mobile у D&S | 16 перевірок, перше натискання працює, мобільний режим встановлюється коректно |
| Форма та аналітика | 4 локальні успішні сценарії, збереження тексту при помилці й повторна відправка; 17 перевірок handler; consent та відсутність передачі персональних полів у події перевірені |
| Продуктивність | Лише потрібний мовний JS; початковий JS близько 143–146 КБ gzip; відсутність повторного завантаження JS при навігації в межах мови |

Додатково виконано чинний mobile-аудит у режимі `vite preview` з кейсом D&S: 336 основних перевірок на шести мобільних ширинах; додатково перевірено горизонтальну орієнтацію та меню. Переповнення, замалі елементи керування й помилки не виявлені. Після останньої правки прев’ю повторно пройдено весь основний production-аудит.

Скриншоти й машинні звіти: `.visual-audit/predeploy/` та `.visual-audit/performance/` (локальні, ігноруються Git). Для перегляду готової збірки: `npm.cmd run preview -- --host 127.0.0.1`; адреса `http://127.0.0.1:4173/uk/`.

## Межі локальної перевірки

HTTP-правила перевірено локально за згенерованим `_redirects`, з моделлю статичних файлів Netlify. Це не запит до реального CDN. Фактичні production HTTPS, CDN, host redirects, захищені змінні Netlify та доставку заявки в Telegram слід перевірити після вашого деплою. Handler і браузерні форми протестовані з локальними заглушками, без зовнішніх повідомлень. Польові Core Web Vitals та індексація Google локально не визначаються.
